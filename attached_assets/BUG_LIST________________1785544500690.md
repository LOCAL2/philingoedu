# รายการปัญหาที่พบ + คำสั่งแก้ไขสำหรับ AI

> กฎการทำงานทั่วไป (ใช้กับทุกข้อด้านล่าง):
> 1. ห้ามแก้ไฟล์ที่ไม่เกี่ยวข้องกับจุดที่ระบุในแต่ละข้อ
> 2. แก้ทีละข้อ ทดสอบผ่านแล้วค่อย commit แล้วค่อยไปข้อถัดไป ห้ามแก้หลายข้อพร้อมกัน
> 3. ห้ามบอกว่า "แก้เสร็จแล้ว" โดยไม่มีหลักฐาน (diff + ยืนยันว่า deploy แล้ว + ทดสอบเปิดเว็บจริงแล้วเห็นผล)
> 4. ทุกข้อที่เกี่ยวกับมือถือ ต้องทดสอบที่ขนาดจอ 375px และ 390px จริงๆ ก่อนบอกว่าเสร็จ

---

## บั๊กที่ 1: หน้ากิจกรรม (Activity section) ใน Landing Page ไม่อัปเดตบนมือถือ

**อาการ:** แก้ไขแล้วตาม preview/desktop แต่เปิดบนมือถือยังเป็นแบบเดิม

**คำสั่งตรวจสอบ (ทำก่อน ห้าม apply):**
```
1. หา component ที่ render ส่วนกิจกรรมในหน้า Landing Page
2. เช็คว่ามี component คนละตัวสำหรับ Desktop/Mobile หรือไม่ (เช่น ActivityDesktop.tsx, ActivityMobile.tsx)
   ถ้ามีสองตัว การแก้ไฟล์เดียวจะไม่ส่งผลกับอีกไฟล์ นี่คือสาเหตุที่เป็นไปได้มากที่สุด
3. เช็คว่ามี cache (build cache, service worker, CDN cache) ที่ทำให้มือถือโหลดเวอร์ชันเก่าหรือไม่
4. รายงานว่าไฟล์ไหนคือไฟล์จริงที่ควบคุมการแสดงผลบนมือถือ
```

---

## บั๊กที่ 2: Banner กิจกรรมหน้าแรก คลิกไม่ได้

**อาการ:** banner "Cebu Education Fair 2026" ที่หน้าแรก กดแล้วไม่มีอะไรเกิดขึ้น

**คำสั่งตรวจสอบ+แก้:**
```
1. หา component banner กิจกรรมในหน้าแรก
2. เช็คว่ามี onClick/href กำหนดไว้หรือไม่ ถ้าไม่มีให้เพิ่มลิงก์ไปหน้ากิจกรรมหรือหน้าลงทะเบียน
3. เช็คว่ามี element อื่นซ้อนทับ (overlay) บัง click area อยู่หรือไม่ (z-index ผิด)
4. เช็คว่า pointer-events ถูกปิดไว้โดยไม่ตั้งใจหรือไม่ (CSS pointer-events: none)
```

---

## บั๊กที่ 3: หน้ารีวิว คลิกแล้วไม่มีข้อมูล / ไม่ตรงกับ Admin Panel

**อาการ:** กดดูรีวิวแล้วไม่มีข้อมูลขึ้น หรือข้อมูลที่เห็นไม่ตรงกับที่ใส่ไว้ใน admin panel

**คำสั่งตรวจสอบ:**
```
1. หาว่าหน้ารีวิวดึงข้อมูลจากที่ไหน (API endpoint, database table, หรือ static file)
2. เทียบกับ admin panel ว่าเขียน/บันทึกข้อมูลรีวิวลงที่เดียวกันหรือไม่ 
   (สาเหตุที่พบบ่อย: admin panel บันทึกลง table/collection หนึ่ง แต่หน้าเว็บดึงจากอีกที่หนึ่ง)
3. เช็คว่า API endpoint ที่ดึงรีวิวมา ทำงานถูกต้องหรือไม่ (เปิด Network tab เช็ค response)
4. เช็คว่ามีการ cache ข้อมูลรีวิวไว้นานเกินไปหรือไม่ ทำให้ข้อมูลใหม่จาก admin ไม่อัปเดต
5. รายงานผลก่อนแก้
```

## บั๊กที่ 4: หน้าสถาบัน (School) - ราคาค่าเรียนมองไม่เห็นเมื่อกด "ประเมิน"

**อาการ:** กดปุ่มประเมินราคาแล้ว ข้อมูลราคาโผล่ไปทางขวา มองไม่เห็น ต้องเลื่อนจอไปดู

**คำสั่งแก้:**
```
1. หา component แสดงผลราคาหลังกด "ประเมิน" ในหน้าสถาบัน
2. เช็คว่า layout ใช้ width ตายตัว (px) หรือดันเนื้อหาล้นขวาหรือไม่
3. แก้ให้ผลลัพธ์ราคาแสดงอยู่ใน viewport เสมอ (ไม่ล้นขวา ไม่ต้อง scroll แนวนอนเพื่อดู)
4. ทดสอบที่ 375px, 390px ต้องเห็นราคาครบทันทีโดยไม่ต้องเลื่อนซ้าย-ขวา
```

## บั๊กที่ 5: ตารางเปรียบเทียบราคา และตารางเรียนรายวัน มองไม่เห็นครบ

**อาการ:** ตารางกว้างเกินจอ เห็นแค่บางส่วน ต้องการให้ลาก (swipe) ดูส่วนที่เหลือได้

**คำสั่งแก้:**
```
1. หา component ตาราง "เปรียบเทียบราคา" และ "ตารางเรียนรายวัน" ในหน้าสถาบัน
2. ห่อตารางด้วย container ที่มี overflow-x: auto และ -webkit-overflow-scrolling: touch 
   (เพื่อให้ swipe ลากดูได้ลื่นบน iOS)
3. เพิ่ม visual indicator บอกว่ายังลากดูต่อได้ (เช่น เงาจางๆ ด้านขวาของตาราง หรือลูกศร)
4. ห้ามให้ scroll ของตารางไปกระทบ scroll ของทั้งหน้า (เฉพาะในกรอบตารางเท่านั้น)
5. ทดสอบบนมือถือจริงว่าลากนิ้วซ้าย-ขวาดูตารางได้ลื่น ไม่มีอาการกระตุก
```

---

## บั๊กที่ 6: วิดีโอไม่แสดง (ใส่ URL ของ CIA ไปแล้ว)

**อาการ:** ใส่ URL วิดีโอของสถาบัน CIA แล้ว แต่วิดีโอไม่ขึ้น

**คำสั่งตรวจสอบ:**
```
1. หา field/component ที่เก็บ URL วิดีโอของสถาบัน CIA
2. เช็คว่า URL ที่ใส่ไปเป็นลิงก์ตรงจาก YouTube/Vimeo หรือเป็น embed link 
   (ถ้าใส่ลิงก์หน้าเว็บปกติ เช่น youtube.com/watch?v=xxx อาจต้องแปลงเป็น embed URL 
   เช่น youtube.com/embed/xxx ก่อนถึงจะแสดงผลได้)
3. เช็คว่า component เล่นวิดีโอ (video player/iframe) รองรับ URL ที่ใส่มาหรือไม่
4. เช็ค Console ว่ามี error เกี่ยวกับ CORS หรือ embed ถูกปฏิเสธหรือไม่
5. รายงานสาเหตุก่อนแก้ไข
```

## บั๊กที่ 7: ราคาโปรโมชั่น แสดงผลบนมือถือมองไม่เห็น (ต้องเลื่อนซ้าย)

**อาการ:** เหมือนบั๊กที่ 4 คือเนื้อหาล้นขวา ต้องเลื่อนจอไปทางซ้ายถึงจะเห็น

**คำสั่งแก้:**
```
1. หา component แสดงราคาโปรโมชั่น
2. เช็คเหมือนบั๊กที่ 4 ว่ามี width/margin ตายตัวที่ดันเนื้อหาออกนอกจอหรือไม่
3. แก้ให้อยู่ใน viewport พอดีทุกขนาดจอ (320px ขึ้นไป)
4. ทดสอบที่ 375px, 390px
```

## ลำดับการทำงานที่แนะนำ

ส่งให้ AI ทำทีละบั๊ก **เรียงตามนี้** (ง่ายไปยาก ลดความเสี่ยงกระทบกัน):
1. บั๊กที่ 2 (banner คลิกไม่ได้) — แก้ง่าย จุดเดียว
2. บั๊กที่ 6 (วิดีโอไม่แสดง) — แก้ง่าย จุดเดียว
3. บั๊กที่ 4 และ 7 (ราคาล้นขวา) — CSS แก้คล้ายกัน ทำพร้อมกันได้
4. บั๊กที่ 5 (ตาราง scroll) — CSS layout
5. บั๊กที่ 1 (activity ไม่อัปเดตมือถือ) — ต้องตรวจโครงสร้างก่อน อาจซับซ้อน
6. บั๊กที่ 3 (รีวิวไม่ตรงกับ admin) — เกี่ยวกับ backend/API ต้องตรวจละเอียดที่สุด ทำท้ายสุด
