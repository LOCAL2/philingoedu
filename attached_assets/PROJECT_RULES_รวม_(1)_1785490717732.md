# กฎการทำงานของ AI ในโปรเจกต์นี้ (ห้ามฝ่าฝืน)

> ไฟล์นี้ต้องถูกอ่านโดย AI ก่อนแก้ไขโค้ดทุกครั้ง ไม่ว่าจะสั่งงานเรื่องอะไรก็ตาม

---

## หมวดที่ 1: กฎพื้นฐาน ป้องกันโค้ดเก่าถูกทับ/หาย

1. ห้ามแก้ไข ลบ หรือ generate โค้ดใหม่ทับไฟล์/ฟังก์ชันที่ไม่เกี่ยวข้องกับงานที่สั่งในคำสั่งนั้นๆ
2. แก้เฉพาะไฟล์และส่วนที่ถูกระบุเท่านั้น ส่วนอื่นที่ทำงานได้แล้วห้ามแตะ
3. ก่อนแก้ไขทุกครั้ง ให้สรุปก่อนว่า:
   - จะแก้ไฟล์ไหน
   - บรรทัด/ฟังก์ชันไหน
   - ทำอะไรบ้าง
   แล้วรอการยืนยันก่อน apply จริง
4. หลังแก้เสร็จ ให้สรุป diff (ก่อน-หลัง) ให้ตรวจสอบได้เสมอ
5. ห้ามเปลี่ยน library, framework version, หรือโครงสร้างโปรเจกต์เดิม เว้นแต่จะถูกสั่งให้เปลี่ยนโดยตรง
6. ห้าม auto-generate ไฟล์ใดๆ ใหม่ทั้งไฟล์ หากแก้แค่บางส่วนได้ ให้แก้เฉพาะจุดนั้น
7. แก้เสร็จ + เทสผ่านแต่ละจุด ให้ commit ทันทีก่อนไปแก้จุดถัดไป (อย่ารวมหลายงานไว้ commit เดียว)
8. งานใหญ่ให้แตกเป็นสเต็ปเล็กๆ แก้ทีละไฟล์ ห้ามแก้หลายไฟล์ใหญ่พร้อมกันในคำสั่งเดียว

---

## หมวดที่ 2: ไฟล์ภาษา (i18n / Locale) ห้ามพังซ้ำ

1. ไฟล์ locale (เช่น `th.json`, `en.json` หรือไฟล์แปลภาษาไทย/อังกฤษ) คือไฟล์ที่บอบบางที่สุดในโปรเจกต์
2. ห้าม AI แก้ไฟล์ locale เว้นแต่ถูกสั่งให้แก้เรื่องภาษาโดยตรงเท่านั้น
3. ก่อนแก้ไขเรื่องอื่น (admin panel, email, ฟีเจอร์ใหม่ ฯลฯ) ต้องเช็คก่อนว่าการแก้นั้นจะไม่ไปกระทบ/เขียนทับไฟล์ locale
4. ถ้าจำเป็นต้องแก้ไฟล์ locale ต้อง backup ไฟล์เดิมก่อนทุกครั้ง (เช่น คัดลอกเป็น `th.json.backup`)
5. ห้าม regenerate ไฟล์ locale ใหม่ทั้งไฟล์ ให้แก้เฉพาะ key ที่มีปัญหาเท่านั้น
6. แก้ไฟล์ locale เสร็จ ให้ commit แยกเฉพาะไฟล์นี้ทันที ก่อนไปแตะไฟล์อื่น

---

## หมวดที่ 3: Responsive Design รองรับทุกอุปกรณ์

1. ใช้แนวทาง Mobile-First (เขียน style สำหรับมือถือก่อน แล้วขยายด้วย media query สำหรับจอใหญ่)
2. ใช้หน่วยที่ยืดหยุ่น (%, rem, vw/vh, flex, grid) แทนค่าตายตัวเป็น px
3. ต้องมี meta viewport ในทุกหน้า:
   `<meta name="viewport" content="width=device-width, initial-scale=1.0">`
   (ห้ามใส่ `maximum-scale=1` เพราะจะบล็อกการซูม ไม่ดีต่อการเข้าถึง)
4. รองรับ breakpoint อย่างน้อย:
   - มือถือจอเล็ก: 320px–480px
   - มือถือจอใหญ่/แนวนอน: 481px–767px
   - แท็บเล็ต (iPad): 768px–1024px
   - เดสก์ท็อป: 1025px ขึ้นไป
5. รูปภาพ/วิดีโอต้องปรับขนาดอัตโนมัติ: `max-width: 100%; height: auto;`
6. ปุ่ม/ลิงก์ต้องกดง่ายบนมือถือ อย่างน้อย 44x44px (touch target มาตรฐาน)
7. ทุก container หลักต้องจัดการ overflow ให้เหมาะสม ห้ามเกิด horizontal scroll บนจอมือถือ
8. ต้องแสดงผลสอดคล้องกันบน Chrome (Desktop/Mobile), Safari (iPhone/iPad), Edge

---

## หมวดที่ 4: SEO Friendly

1. ทุกหน้าต้องมี `<title>` และ `<meta name="description">` ที่เหมาะสม
2. โครงสร้าง Heading ต้องถูกลำดับ (h1 หนึ่งตัวต่อหน้า ตามด้วย h2, h3 ตามลำดับ)
3. รูปภาพทุกรูปต้องมี alt text
4. ใช้ structured data (schema.org) ตามความเหมาะสมของธุรกิจ
5. ต้องมีไฟล์ `sitemap.xml` และ `robots.txt`
6. URL ต้องอ่านง่าย ไม่มีพารามิเตอร์ที่ไม่จำเป็น
7. เว็บต้องโหลดเร็ว: compress รูปภาพ, lazy load, minify CSS/JS
8. ต้องมี Open Graph tags (og:title, og:description, og:image) สำหรับการแชร์ลิงก์

---

## หมวดที่ 5: ป้องกันข้อมูลหายตอน Restart Server

1. ค่า config, environment variables, และการเชื่อมต่อฐานข้อมูล ต้องไม่หายเมื่อ restart server
2. ถ้ามีการเก็บข้อมูลแบบ in-memory ต้องเปลี่ยนไปเก็บใน database หรือไฟล์แทน
3. ก่อน apply การเปลี่ยนแปลงที่ต้อง restart server ให้แจ้งเตือนก่อน พร้อมสรุปว่าอะไรจะถูกกระทบบ้าง
4. commit โค้ดลง Git ทุกครั้งที่แก้เสร็จและเทสผ่านแล้ว ก่อนแก้จุดถัดไป

---

## หมวดที่ 6: ตัวเลือกแผนเรียน/ห้องพัก/ระยะเวลา ต้องเป็น Dropdown เท่านั้น

1. ตัวเลือก "แผนการเรียน", "เลือกห้องพัก", "ระยะเวลา" ต้องเป็น `<select>` dropdown 
   หรือ dropdown component ของ library ที่ใช้อยู่ **ห้ามเป็นปุ่มเรียงแนวนอน (button row / pill) เด็ดขาด**
2. dropdown ต้องกว้างเต็ม container ของมันเสมอ ห้ามล้นขอบจอในทุกขนาดหน้าจอ (320px ขึ้นไป)
3. ปุ่ม/กล่อง dropdown ต้องมีความสูงอย่างน้อย 44px เพื่อให้กดง่ายบนมือถือ
4. **ห้าม AI เปลี่ยน component นี้กลับเป็นปุ่มแถวแนวนอนอีกไม่ว่ากรณีใด** แม้จะแก้ไขเรื่องอื่นที่อยู่ใกล้กันก็ตาม
5. ก่อนแก้ไขส่วนใดๆ ที่อยู่ใกล้กับ component นี้ ให้เช็คก่อนว่าจะไม่ไปกระทบโครงสร้าง dropdown ที่ทำไว้แล้ว

---

## หมวดที่ 7: ปุ่มลอย (Floating Buttons: LINE, Messenger, TikTok, โทร, Scroll-to-top)

1. ห้ามให้ปุ่มลอยทั้งหมดแสดงพร้อมกันแบบเรียงซ้อนจนบังเนื้อหาสำคัญ (เช่น ตารางราคา, ปุ่ม action หลัก, ข้อความสำคัญ)
2. ให้ยุบปุ่มลอยเป็นปุ่มหลัก (FAB) ปุ่มเดียว กดแล้วค่อยขยายเมนูออกมา หรือขยับตำแหน่งไม่ให้ทับเนื้อหา
3. ต้องเช็คทุกครั้งที่แก้ layout ว่าปุ่มลอยไม่บังเนื้อหาบนจอเล็กสุด (320px–375px)
4. ห้ามลบฟังก์ชันปุ่มลอยออกทั้งหมดโดยไม่ได้รับอนุญาต ให้แค่จัดตำแหน่ง/พฤติกรรมใหม่เท่านั้น

---

## หมวดที่ 8: ตารางที่กว้างเกินจอ (เช่น ตารางเปรียบเทียบราคา)

1. ตารางทุกตัวต้องห่อด้วย container ที่มี `overflow-x: auto` เพื่อ scroll แนวนอนได้เฉพาะในตาราง (ห้าม scroll ทั้งหน้า)
2. ต้องมี indicator ให้ผู้ใช้รู้ว่ายัง scroll ดูต่อได้ (เช่น เงาจางๆ ด้านขวาของตาราง)
3. ถ้าตารางซับซ้อนเกินไปสำหรับจอมือถือ ให้พิจารณาเปลี่ยนเป็น layout แบบ card ต่อคอลัมน์แทน
4. ห้ามปล่อยให้ตารางดันความกว้างหน้าเว็บทั้งหน้าจนเกิด horizontal scroll ทั้งหน้า (เช็คว่าไม่มี element ไหนกว้างเกิน 100vw)

---

## หมวดที่ 9: ก่อนเริ่มงานทุกครั้ง AI ต้องทำตามลำดับนี้

1. อ่านไฟล์นี้ (`PROJECT_RULES.md` / `replit.md`) ก่อนเสมอ
2. ระบุให้ชัดว่าจะแก้ไฟล์ไหนบ้าง และยืนยันว่าจะไม่กระทบไฟล์อื่น
3. รอการยืนยันจากผู้ใช้ก่อน apply
4. แก้เสร็จ → เทสบนขนาดจอ 375px (iPhone SE/mini) และ 390px (iPhone ทั่วไป) ต้องเห็นเนื้อหาครบ ไม่มีอะไรโดนตัดขอบหรือโดนปุ่มลอยบัง
5. commit → บันทึกสรุปการเปลี่ยนแปลงไว้ใน `REGRESSION_TEST_CHECKLIST.md`
