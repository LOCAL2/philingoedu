กฎการทำงาน (ห้ามฝ่าฝืน):
1. ห้ามแก้ไขโค้ดใดๆ ในคำสั่งนี้ ทำหน้าที่ตรวจสอบและบันทึกเท่านั้น
2. ต้องรายงานผลทุกข้อ ห้ามข้าม ห้ามสรุปว่า "เสร็จแล้ว" โดยไม่มีหลักฐาน

═══════════════════════════════
ขั้นตอนที่ 1: รวบรวมรายการที่แก้ไปทั้งหมดในทุกเซสชัน
═══════════════════════════════
1. ดู git log ทั้งหมด (หรือ commit history) ย้อนหลังตั้งแต่เริ่มบทสนทนานี้
2. สรุปเป็นตาราง: [วันที่/เวลา] → [ไฟล์ที่แก้] → [สรุปสิ่งที่แก้] → [commit hash]
3. แยกให้ชัดว่าอันไหน "แก้เสร็จ + deploy แล้ว" กับอันไหน "แก้เสร็จแต่ยังไม่ deploy"

═══════════════════════════════
ขั้นตอนที่ 2: เช็ค Deploy Status ปัจจุบัน
═══════════════════════════════
1. เช็คเวลา deploy ล่าสุด เทียบกับเวลา commit ล่าสุดของทุกไฟล์
2. ถ้ามีไฟล์ไหนที่ commit แล้วแต่ deploy ไม่ทัน ให้ระบุชัดเจนว่าไฟล์ไหนบ้าง
3. รายงานว่า "production ตอนนี้ตรงกับโค้ดล่าสุดกี่เปอร์เซ็นต์" พร้อมรายชื่อจุดที่ยังไม่ตรง

═══════════════════════════════
ขั้นตอนที่ 3: ทดสอบตาม Pre-Deploy Checklist (ทุกข้อ)
═══════════════════════════════
ทดสอบและรายงานผล ✅/❌ ทีละข้อ:
- [ ] Banner หน้าแรกคลิกได้
- [ ] Hero overlay หน้าสัมมนา ทับภาพถูกต้องบน 320-390px
- [ ] /activities redirect ไป /seminars
- [ ] Dropdown แผนเรียน/ห้องพัก/ระยะเวลา ในหน้าสถาบัน
- [ ] ตารางเปรียบเทียบราคา/ตารางเรียนรายวัน scroll ได้
- [ ] ราคาประเมิน/โปรโมชั่น ไม่ล้นขวาจอมือถือ
- [ ] ปุ่มลอย LINE/Messenger/TikTok ไม่บังเนื้อหา
- [ ] ระบบภาษา TH/EN จำค่าที่เลือกไว้ (localStorage)
- [ ] จำนวนรีวิวตรงกับ Admin Panel
- [ ] SEO per-school (Title/Description/Keywords/H1) บันทึกและแสดงถูกต้อง
- [ ] SEO Global (/admin/settings) บันทึกได้จริง ไม่เป็น [object Object]
- [ ] ปุ่ม LINE ทุกจุดในเว็บ ชี้ไป @philingo ไม่ใช่ @thaistudyabroad
- [ ] หัวข้อหน้าแก้ไขสถาบัน แสดงชื่อสถาบันถูกต้อง (ไม่ใช่ "undefined")

═══════════════════════════════
ขั้นตอนที่ 4: ทดสอบบน Production จริง (ไม่ใช่ preview)
═══════════════════════════════
1. เปิด production URL จริงด้วยตัวเอง (fetch เนื้อหามาเช็ค ไม่ใช่แค่ดู preview)
2. เทียบผลกับขั้นตอนที่ 3 อีกครั้งบน production จริง
3. ถ้าผลต่างกันระหว่าง preview กับ production ให้ระบุว่าต่างกันตรงไหน และสาเหตุคืออะไร

═══════════════════════════════
ขั้นตอนที่ 5: สร้างระบบบันทึก Deploy Log (ถาวร ใช้ต่อในอนาคต)
═══════════════════════════════
1. สร้างไฟล์ DEPLOY_LOG.md ในโปรเจกต์ (ถ้ายังไม่มี)
2. ทุกครั้งที่ deploy จากนี้ไป ให้บันทึกอัตโนมัติ (หรือ manual เป็นกฎ) ดังนี้:
   - วันที่/เวลา deploy
   - ไฟล์ที่เปลี่ยนแปลงในรอบนั้น (list)
   - สรุปสิ่งที่แก้ (1-2 บรรทัด)
   - ผลทดสอบ pre-deploy checklist (ผ่าน/ไม่ผ่าน)
   - Commit hash อ้างอิง
3. เพิ่มกฎใน PROJECT_RULES.md ว่า "ห้าม deploy โดยไม่บันทึกลง DEPLOY_LOG.md" 
   เพื่อให้ตรวจสอบย้อนหลังได้เสมอว่า deploy รอบไหนทำอะไรไปบ้าง ถ้าเว็บไม่ตรงจะได้ไล่เช็คง่าย

═══════════════════════════════
สรุปผลสุดท้าย
═══════════════════════════════
รายงานสรุป:
1. รายการที่ผ่านครบ ✅
2. รายการที่ยังไม่ผ่าน ❌ พร้อมสาเหตุที่ทราบ (ถ้ามี)
3. Production ตรงกับโค้ดล่าสุดหรือไม่ (เปอร์เซ็นต์/รายละเอียด)
4. แนะนำว่าควรทำอะไรต่อเป็นลำดับแรก
